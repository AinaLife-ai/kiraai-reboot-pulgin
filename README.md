# 上下文重置 · Context Reboot

KiraAI 的会话上下文重置插件。支持**只清空上下文、不删会话**，可选在重开时生成**累积摘要**，并提供指令与 LLM 工具两种入口。

- 指令触发：`/reboot`（清空）、`/resume`（清空 + 强制摘要）
- 模型自主：`reset_context` 工具（可关闭）
- 与 [Auto Delete Session](https://github.com/znq19/KiraAI_auto_delete_session_plugin)（ADS）兼容共存

---

## 功能特性

| 特性 | 说明 |
|---|---|
| 🧹 **只清空上下文，不删会话** | 保留会话标题、会话描述、**会话级能力开关**（图像识别 / TTS / STT / 生图 / 转发解析）与时间戳。旧版本用 `delete_session()` 会把这些一起删掉。 |
| 📝 **重开摘要（默认关）** | 重置前把即将被清空的历史压缩成摘要写回新上下文，避免彻底失忆。 |
| 🧠 **累积摘要** | 旧摘要 + 本次新增合并成一份，长期反复重置也不会逐层丢失信息。 |
| ⚡ **默认不堵塞** | `async` 模式：立即重置并回复，摘要后台生成后补写。 |
| 🎛 **两条指令各司其职** | `/reboot` = 硬重置；`/resume` = 带记忆的软重置（强制摘要，不受开关影响）。默认均关闭。 |
| 🤖 **模型自主重置** | 用户说「重新开始 / 忘掉之前的内容」时模型可自行调用工具（默认开启，可关闭）。 |
| 🧩 **与 ADS 兼容** | 摘要头互相认领，不会出现两份互相打架的摘要；指令关键词重叠时自动让位给 ADS。 |
| 🔐 **权限控制** | 可选白名单；开启但白名单为空时**拒绝所有用户**（fail-closed）。 |
| 🗂 **配置向后兼容** | 1.0 的扁平配置项会被自动识别并迁移。 |

## 安装

把本仓库放进 KiraAI 的 `data/plugins/` 目录（目录名任意），重启 KiraAI 即可。

```
data/plugins/reboot_plugin/
  main.py  summarizer.py  compat.py  __init__.py
  manifest.json  schema.json  icon.png
```

> `plugin_id` 固定为 `reboot_plugin`，请勿修改目录里的 `manifest.json` 的 `plugin_id` —— 配置保存在 `data/config/plugins/<plugin_id>.json`，改了会丢失既有配置。

## 使用

### 指令

两条指令**默认都是关闭的**，需要先在插件设置里打开。

| 指令 | 默认关键词 | 行为 | 受「重开时生成摘要」开关影响 |
|---|---|---|---|
| 重开指令 | `/reboot` | 清空当前会话上下文 | **是**：开关开则附带摘要 |
| 摘要重开指令 | `/resume` | 清空上下文 **+ 强制生成累积摘要** | **否**：永远摘要 |

关键词是**整句匹配**（大小写不敏感，需完全相等），可在设置里改成任意词、每行一个。

```
用户: /reboot
机器人: ✅ 已重置本会话上下文，我们可以重新开始对话了！

用户: /resume
机器人: ✅ 已重置本会话上下文，已注入累计摘要，我们可以重新开始对话了！
```

指令消息本身不会进入上下文，也不会触发模型。

### 模型自主调用

默认开启。用户说「忘掉我们刚才说的」「重新开始对话」这类话时，模型可以调用 `reset_context` 工具重置当前会话。

关闭后该工具对模型完全不可见（不只是拒绝调用）。

### 权限控制

开启「指令启用权限控制」后，只有白名单内用户能执行两条指令。

> ⚠️ 开启权限控制但白名单为空时，**所有用户都会被拒绝**。这是刻意的安全默认：空名单不应等于「不设防」。

## 配置项

### 清空方式

| 配置项 | 默认 | 说明 |
|---|---|---|
| 清空方式 | `memory_only` | `memory_only`=只清空记忆，保留会话标题/描述/能力开关；`delete_session`=删除会话再重建（旧行为，元信息会丢失） |
| 丢弃待处理缓冲消息 | 开 | 清空前丢弃尚未进入上下文的缓冲消息 |

### 指令触发

| 配置项 | 默认 | 说明 |
|---|---|---|
| 启用重开指令 | 关 | 打开 `/reboot` |
| 重开指令关键词 | `/reboot` | 每行一个 |
| 启用摘要重开指令 | 关 | 打开 `/resume` |
| 摘要重开指令关键词 | `/resume` | 每行一个，**注意带 e** |
| 指令启用权限控制 | 关 | 开启后仅白名单可用 |
| 指令白名单 | 空 | 用户 ID，每行一个 |
| 成功反馈 / 权限不足反馈 / 错误反馈 / 无历史反馈 | — | 可用 `{summary}`、`{error}` 占位符 |

### bot 自主重置

| 配置项 | 默认 | 说明 |
|---|---|---|
| 允许 bot 自主重置上下文 | 开 | 关闭后 `reset_context` 工具对模型不可见 |

### 重开摘要

| 配置项 | 默认 | 说明 |
|---|---|---|
| 重开时生成摘要 | 关 | 总开关，作用于 `/reboot` 与工具路径 |
| 摘要模式 | `async` | `async`=不堵塞；`sync`=等摘要生成完再回复 |
| 摘要模型 | 跟随默认 | 留空则回退：快速模型 → 默认模型 |
| 摘要超时（秒） | 60 | 超时则放弃摘要直接重置 |
| 摘要输入上限（字符） | 10000 | 从最新往前截取；`0`/`-1` = 不限 |
| 摘要输出上限（字符） | 5000 | 超出则截断；`0`/`-1` = 不限 |
| 摘要提示词 | 内置 | 可含 `{text}` 占位符 |
| 累积摘要（推荐） | 开 | 旧摘要与新增合并 |
| 摘要合并提示词 | 内置 | 需含 `{old_summary}` / `{new_summary}` |
| 摘要自压缩提示词 | 内置 | 需含 `{summary}` |
| 摘要合并超时（秒） | 120 | 超时退化为拼接 |
| 摘要保活（内存桥） | 开 | 摘要头被框架窗口挤掉时，临时补回当前请求（**建议保持开启**，见下） |
| 摘要详细日志 | 关 | 排查用 |

### 关于「摘要保活」

一句话：**框架默认的会话窗口只有 10 轮**（`bot_config.bot.max_memory_length` 默认 `10`），而摘要固定在记忆的**第一块**，所以它是最先被框架从队首丢弃的那一块——活跃会话聊十几轮就会把它挤出去。

开启「摘要保活」后，摘要被挤掉的期间本插件会在**每次请求**里临时把它补回（只作用于这一次请求，不写盘），上下文布局与它还在时**完全一致**，因此不影响前缀缓存。

即使关掉它信息也不会真的丢：摘要同时持久化在插件数据目录里，下次重开时会作为合并基底重新写回。关掉的代价只是「被挤掉的这段时间里模型看不到摘要」。

### 兼容

| 配置项 | 默认 | 说明 |
|---|---|---|
| 与 Auto Delete Session 兼容 | 开 | 摘要头共享标记 + 指令重叠让位 |
| 检测到其它记忆插件时告警 | 开 | 仅告警，不影响其它插件 |

## 与 Auto Delete Session 共存

两个插件的职责不同，可以同时安装：

| | `/reboot`（本插件） | `/resume`（本插件） | `/resum`（ADS） |
|---|---|---|---|
| 行为 | 清空上下文 | 清空 + 强制摘要 | 压缩重开，**保留最近 N 轮** + 摘要 |
| 默认关键词 | `/reboot` | `/resume` | `/resum` |

**两条约定（都自动生效）：**

1. **摘要头互相认领。** 两个插件都把摘要写在记忆的第一块，并共用同一个标记前缀。这样 ADS 不会在自己运行时把它的旧摘要「桥回」刚被本插件清空的上下文；反之亦然。**同一时刻上下文里始终只有一份摘要。**
2. **指令重叠时让位。** 两个插件都用 `on.im_message`（同优先级）拦截指令并 `event.stop()`，同优先级下「谁先注册谁赢」取决于插件加载顺序，结果不确定。因此加载时若检测到 ADS 已启用，本插件会自动把与 ADS 重叠的关键词从自己这边移除，并打印告警。

> ⚠️ `/resume` 与 `/resum` 只差一个字母，请注意区分：前者是本插件的「清空+摘要」，后者是 ADS 的「保留最近若干轮的压缩重开」。打错的话指令不会生效。

关闭「与 Auto Delete Session 兼容」即可退回完全隔离模式（各自维护摘要头，可能出现重复）。

## 从 1.0 升级

- **无感升级，无需改动配置。** 旧的扁平配置项（`command_prefix`、`enable_permission`、`allowed_users`、`success_message` 等）会被自动识别并迁移到新的分组配置里；如果你没有改过对应项，旧值会继续生效。
- **行为变化**：不再删除会话，只清空上下文 —— 会话标题、描述、会话级能力开关都会保留。
- **工具改名**：`clear_context` → `reset_context`。对使用者无影响。
- **指令默认关闭**：`/reboot` 与 `/resume` 都需要先在设置里启用。1.0 里 `/reboot` 是始终可用的，升级后请到插件设置中打开「启用重开指令」。
- 新增可选功能：重开摘要、LLM 工具开关、权限白名单语义修正、与 ADS 兼容。
